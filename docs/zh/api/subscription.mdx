# 订阅管理 API 文档

## 基础路径
`/subscriptions`

## 接口列表

### 获取订阅列表
```http
GET /
```

**查询参数**
```typescript
{
  searchValue?: string,  // 搜索关键词
  ids?: string          // JSON 编码的 ID 数组，例如 "[1,2]"
}
```

### 创建订阅
```http
POST /
```

**请求体**
```typescript
{
  type: string,           // 订阅类型
  schedule?: string,      // 定时计划
  interval_schedule?: {   // 间隔计划
    type: string,
    value: number
  },
  name?: string,          // 名称
  url: string,           // 订阅地址
  whitelist?: string,    // 白名单
  blacklist?: string,    // 黑名单
  skipFiles?: string,    // 不同步文件，每行一个相对路径或以 / 结尾的目录
  branch?: string,       // 分支
  dependences?: string,  // 依赖
  pull_type?: string,    // 拉取类型
  pull_option?: object,  // 拉取选项
  extensions?: string,   // 扩展
  sub_before?: string,   // 执行前脚本
  sub_after?: string,    // 执行后脚本
  schedule_type: string, // 计划类型
  alias: string,        // 别名
  proxy?: string,       // 代理
  autoAddCron?: boolean, // 自动添加定时任务
  autoDelCron?: boolean  // 自动删除定时任务
}
```

### 订阅文件同步规则（待修复版本发布）

黑名单用于阻止匹配文件创建定时任务；匹配“依赖文件”的脚本仍会同步。需要保留本地修改时，使用“不同步文件”（`skipFiles`），无需把依赖文件移出依赖规则。

`skipFiles` 每行填写一个**仓库相对路径**，精确匹配文件，目录以 `/` 结尾。它不是正则表达式，也不加订阅目录前缀。例如：

```json
{"skipFiles": "env.js\nconfig/\nsendNotify.js"}
```

这些文件不会被仓库文件、内置通知脚本或本地依赖覆盖；自动删除失效任务也会保留对应的本地文件。该设置不会阻止远端仓库克隆，未匹配的文件仍照常同步。未填写时保持现有行为。本地尚不存在的受保护文件不会被下载，也不会创建没有脚本的任务。

### 更新订阅

```http
PUT /
```

请求体必填 `id: number`、`type: string`、`url: string`、`alias: string`；其余字段参考创建订阅，更新时 `schedule_type` 可选。创建时 `interval_schedule.value` 必须大于等于 1。

### 删除订阅

```http
DELETE /
```

请求体为订阅 ID 数组，例如 `[1, 2]`。可选查询参数 `force=true` 会同时删除关联的定时任务、脚本目录和仓库目录；省略时仅删除订阅。

### 获取订阅详情

```http
GET /:id
```

`id` 为数字订阅 ID，响应 `data` 为订阅对象。

### 运行订阅
```http
PUT /run
```

**请求体**
```typescript
number[]  // 订阅ID数组
```

### 获取订阅日志
```http
GET /:id/log
```

查询参数支持 `offset`（非负整数字节偏移）、`limit`（1–1048576 字节）和 `tail`（布尔值）。响应 `data` 是日志文本，同时返回 `offset`、`nextOffset`、`total`、`truncated`；继续读取时使用 `nextOffset`，不要用字符数计算偏移。详见[日志 API](./log)。

### 更新订阅状态
```http

```

**请求体**

```typescript
{
```


## 错误处理
- 所有接口遵循统一的错误处理机制
- 成功响应返回 `{ code: 200, data: ... }`
- 错误日志由 Winston logger 处理

## 注意事项
- 使用 celebrate/Joi 进行参数验证
- cron 表达式由 cron-parser 校验并标准化；订阅与任务、额外定时规则和系统 Node cron 共用调度规则，Node 调度使用 node-cron，详见[定时规则与时区](./crontab#定时规则与时区)
- `schedule_type: "crontab"` 使用 cron 计划；间隔计划通过 `interval_schedule` 独立配置，不按 cron 字段解释
- 支持批量操作（运行、停止、启用、禁用等）
