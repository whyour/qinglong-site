### System Operations

#### Check Updates
```http
PUT /update-check
```

Checks for system updates.

#### Update System
```http
PUT /update
```

Runs `ql update false` in the background to download and verify staged upgrade artifacts, installing dependencies in staging when needed. The initial `200` does not mean that downloading finished or the upgrade was applied. Follow WebSocket `updateSystemVersion` messages for progress and the final `success`/`failed` status. After successful preparation, call the reload endpoint with `{"type":"system"}` to apply the upgrade. See the [maintenance guide](../guide/user-guide/maintenance).

#### Reload System
```http
PUT /reload
```

**Request Body**
```typescript
{
  type?: 'system' | 'data' | '' | null  // system: apply staged upgrade; data: apply staged backup
}
```

Omitting `type` or passing an empty string or `null` only restarts services. This endpoint starts a separate reload process; a `200` response does not mean that reload or health checks have completed.

### Data Management

#### Export Data
```http
PUT /data/export
```

Returns a compressed backup download. Pass a JSON body such as `{"type":["scripts","config","log"]}` to include these additional data directories. Selecting `scripts` automatically includes an existing `script-history` directory. You may also select `script-history` explicitly; it is skipped if it has not been created. Omitting `type` or passing an empty array exports only `db` and `upload`, excluding scripts, history, configuration and logs. `base` denotes the base data, not an extra directory. See the [maintenance guide](../guide/user-guide/maintenance) for a complete backup.

#### Import Data
```http
PUT /data/import
```

**Request**
- Content-Type: `multipart/form-data`
- Field: `data` (file)

Upload the exported `data.tgz`. This endpoint only extracts the backup into the temporary directory. After a successful import, call `PUT /open/system/reload` with `{"type":"data"}` to replace the current data and restart the service. Replacement clears the existing data directory; directories absent from the backup are not retained. Back up current data before applying the import.

### Log Management

#### Get System Logs
```http
GET /log
```

**Query Parameters**
```typescript
{
  startTime?: string,
  endTime?: string,
  limit?: number, // Integer byte limit: 1–1048576; default 1048576
  t?: string     // Optional extra parameter; not used for filtering
}
```


Logs are filtered by file creation date. Start and end times expand to the beginning and end of their respective days; omitted values default to today. The response is raw log text. When it exceeds `limit`, the tail of the selected logs is returned. `X-QL-Log-Total` reports total matching bytes, `X-QL-Log-Truncated` indicates truncation, and `Content-Length` reports returned bytes. This endpoint does not use the regular Log API’s `offset/nextOffset` pagination structure.

#### Delete System Logs
```http
DELETE /log
```

Deletes system logs.

## Error Handling
All endpoints follow the same error handling pattern:
- Errors are passed to the next middleware
- Most successful responses return `{ code: 200, data: ... }`
- Error logging is handled by Winston logger

## Notes
- All routes are protected by celebrate/Joi validation
- File operations use async fs promises
- Temporary files are stored in configured tmp path
- Log files include timestamps in format: `YYYY-MM-DD-HH-mm-ss-SSS`

## Retention and cleanup

Under `/open/system/storage-retention`, `PUT /config` saves retention policy, `POST /preview` previews cleanup, and `POST /cleanup` performs cleanup.

| Field | Type | Description |
| --- | --- | --- |
| `runningInstanceRetentionDays` | number | Required integer retention days, 0–3650 |
| `cronStatRetentionDays` | number | Required integer retention days, 0–3650 |
| `dependenceCacheTypes` | string[] | Optional for preview/cleanup: `node`, `python3`; default empty |
| `compactDatabase` | boolean | Optional for preview/cleanup; default false |
| `confirmation` | string | Required only for cleanup; must be `CLEAN` |

Preview the selected policy before applying cleanup. This example only previews:

```bash
ql system retention-preview --data '{"runningInstanceRetentionDays":30,"cronStatRetentionDays":90,"dependenceCacheTypes":[],"compactDatabase":false}' --json
```

See the [route reference](./routes) for the remaining system endpoints and CLI commands.
